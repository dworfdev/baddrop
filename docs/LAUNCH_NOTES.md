# Запуск: бэкапы, аварийный выключатель, уведомления админу

## 1. Ежедневный бэкап БД
Файлы: `deploy/backup/` (`Dockerfile`, `backup.sh`, `docker-compose.backup.snippet.yml`).

1. Скопируй папку `deploy/backup` на сервер рядом с `docker-compose.yml`.
2. Добавь сервис `db-backup` из `docker-compose.backup.snippet.yml` в свой compose (поправь имя сервиса MySQL, если не `db`).
3. `docker compose up -d --build db-backup`
4. Через ~20 секунд после старта делается первый дамп (проверка), дальше каждый день в 03:00 UTC.
   Дампы лежат в `./backups/baddrop_db_ГГГГ-ММ-ДД_ЧЧММСС.sql.gz`, хранятся 14 дней.
   Логи: `docker compose logs db-backup`.

Важно:
- Бэкап на том же сервере не спасёт, если пропадёт сам сервер. Раз в день копируй папку `backups` на другую машину
  (rsync/scp/rclone по cron) или включи `BACKUP_SEND_TELEGRAM: "true"` (файл придёт в чат уведомлений, но в нём данные игроков).
- Если задан бот уведомлений, придёт сообщение об успехе или ошибке бэкапа.
- Раз в месяц проверяй восстановление на тестовой базе.

Восстановление (останови приложение, потом):
```
gunzip -c backups/baddrop_db_XXXX.sql.gz | docker compose exec -T db mysql -u root -p"$DB_PASSWORD" baddrop_db
```
Если БД пустая или новая, сначала создай её: `CREATE DATABASE baddrop_db;`

## 2. Аварийный выключатель
Админка, блок bankroll: кнопка `[ Emergency stop ]` (с подтверждением) / `[ Resume app ]`.
- Пока включено, любой запрос игрока (в том числе вход и уже открытые сессии) получает 503, а в приложении показывается экран
  «Technical maintenance». Экран сам проверяет статус каждые 20 секунд и возвращает игрока в приложение после выключения.
- Админка и вход в админку работают всегда, чтобы выключатель можно было отключить.
- Флаг хранится в БД (таблица `platform_setting`), поэтому переживает перезапуск. Каждое включение и выключение пишется в аудит
  (`MAINTENANCE_ON` / `MAINTENANCE_OFF`).

## 3. Уведомления админу о новых заявках
Отдельный бот, не тот, через который заходят игроки.
1. В @BotFather создай нового бота и скопируй токен.
2. Открой этого бота и нажми Start (иначе он не сможет тебе писать).
3. Свой числовой Telegram id можно узнать у @userinfobot.
4. В `.env` на сервере:
```
ADMIN_NOTIFY_BOT_TOKEN=токен_второго_бота
ADMIN_NOTIFY_CHAT_ID=твой_telegram_id
```
5. В обоих файлах `application-prod.yaml` и `application-test.yaml` в блок `slots:` (рядом с `telegram:`) добавь:
```
  notify:
    bot-token: ${ADMIN_NOTIFY_BOT_TOKEN:}
    chat-id: ${ADMIN_NOTIFY_CHAT_ID:}
```
6. Перезапусти приложение. Если одна из переменных пустая, уведомления просто выключены.

Что приходит: «New DEPOSIT request» (когда игрок подтвердил оплату) и «New WITHDRAWAL request» с ником и суммой.
Адрес кошелька и хэши в сообщения не попадают. Отправка идёт в фоне после сохранения заявки; если Telegram недоступен,
заявка всё равно создаётся, а в логе появляется предупреждение (без токена).
