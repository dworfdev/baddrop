Mathematical Specification & Technical Requirements: Low-Variance Instant Win Case Opener

1. System Overview
The objective is to implement an Instant Win Case Opener mechanic (similar to a Loot Box or Coin Flip system) with a strictly regulated, low-variance mathematical profile.
When a user spends a fixed entry fee ($2.00) to open a case, the system must trigger an opening sequence and randomly distribute a specific amount of currency. The distribution must guarantee a stable, mathematically proven house edge over a long-term horizon, while maintaining a high Hit Frequency to ensure the player experiences frequent wins.

2. Core Mathematical Formulas
To ensure predictable financial outcomes and strict adherence to gambling mathematics, the engine must implement and validate the following formulas:

2.1. Probability Mass Function
The sum of all configured probabilities within a single case configuration must strictly equal 1.0 (100%).
\(\sum _{i=1}^{n}P_{i}=1.0\)
Where \(P_{i}\) is the probability of outcome \(i\).

2.2. Expected Value (EV) & Return to Player (RTP)
The Expected Value represents the average theoretical payout per single round. The Return to Player (RTP) percentage determines the long-term sustainability and house margin.
\(\text{EV}=\sum _{i=1}^{n}(X_{i}\times P_{i})\)
\(\text{RTP\ (\%)}=\left(\frac{\text{EV}}{\text{Cost}}\right)\times 100\)
Where \(X_{i}\) is the payout amount for outcome \(i\), and \(\text{Cost}\) is the entry fee ($2.00).
• Target Margin: The system must balance the paytable to achieve a target RTP (e.g., 95%, meaning a 5% House Edge).

2.3. Variance (\(\sigma ^{2}\)) Control
To achieve a Low Volatility / Low Variance experience, outcomes must cluster closely around the entry fee. High-value jackpots with extremely low probabilities must be avoided, as they inflate variance.
\(\sigma ^{2}=\sum _{i=1}^{n}\left[P_{i}\times (X_{i}-\text{EV})^{2}\right]\)

3. Algorithmic Requirements (The Payout Logic)
The Random Number Generator (RNG) must use a standard uniform distribution float between 0.0 and 1.0. Because native random number generators cannot natively process weighted probabilities, the backend must implement a Cumulative Distribution Function (CDF) loop (also known as the "Cumulative Sum" or "Interval Mapping" method).
1. Generate a random float \(R \in [0.0, 1.0)\).
2. Iterate through the pre-sorted paytable arrays.
3. Maintain a running cumulative probability sum.
4. Return the prize corresponding to the interval where \(R\) falls.

4. Reference Implementation (Java Example)
Note: The following Java code serves strictly as a structural reference example for the developer to understand the data mapping and validation logic.

import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public class CaseOpenerEngine {

    // Define the structure for each outcome
    public static class Outcome {
        public double winAmount;
        public double probability;

        public Outcome(double winAmount, double probability) {
            this.winAmount = winAmount;
            this.probability = probability;
        }
    }

    private static final double CASE_COST = 2.00;
    private static final List<Outcome> paytable = new ArrayList<>();
    private static final Random rng = new Random();

    static {
        // LOW-VARIANCE CONFIGURATION EXAMPLE (RTP ~ 95%)
        // High hit frequency for values close to the cost entry point
        paytable.add(new Outcome(1.20, 0.40)); // 40% chance (Micro-loss)
        paytable.add(new Outcome(1.80, 0.35)); // 35% chance (Near break-even)
        paytable.add(new Outcome(2.50, 0.20)); // 20% chance (Small win)
        paytable.add(new Outcome(5.00, 0.05)); // 5% chance  (Cap prize to keep variance low)
    }

    /**
     * Verifies the mathematical integrity of the configuration arrays before deployment.
     */
    public static boolean validateMathematics() {
        double totalProbability = 0.0;
        double expectedValue = 0.0;

        for (Outcome outcome : paytable) {
            totalProbability += outcome.probability;
            expectedValue += outcome.winAmount * outcome.probability;
        }

        // Handle potential floating-point precision issues
        if (Math.abs(totalProbability - 1.0) > 0.0001) {
            System.err.println("CRITICAL ERROR: Sum of probabilities must equal 1.0!");
            return false;
        }

        double rtp = (expectedValue / CASE_COST) * 100;
        double houseEdge = 100.0 - rtp;

        System.out.println("=== Math Configuration Verified ===");
        System.out.println(String.format("Expected Value (EV): $%.3f", expectedValue));
        System.out.println(String.format("Return to Player (RTP): %.2f%%", rtp));
        System.out.println(String.format("House Edge (Margin): %.2f%%", houseEdge));
        return true;
    }

    /**
     * Core game loop logic for resolving a case opening via Cumulative Sum.
     */
    public static double openCase() {
        double randomValue = rng.nextDouble(); // Generates a float between 0.0 and 1.0
        double cumulativeProbability = 0.0;

        for (Outcome outcome : paytable) {
            cumulativeProbability += outcome.probability;
            if (randomValue < cumulativeProbability) {
                return outcome.winAmount;
            }
        }

        // Fallback for edge cases due to floating-point rounding
        return paytable.get(paytable.size() - 1).winAmount;
    }

    public static void main(String[] args) {
        if (validateMathematics()) {
            System.out.println("\n=== Simulating 5 Live Rounds ===");
            for (int i = 1; i <= 5; i++) {
                double reward = openCase();
                System.out.println(String.format("Round #%d: Cost: $%.2f | Payout: $%.2f", i, CASE_COST, reward));
            }
        }
    }
}
